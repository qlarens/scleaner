# Разработка и проверка SCleaner

## Файловая очистка

`Catalog` строит явный список `Target`; `Engine` использует его при сканировании и повторно перед очисткой. `Target.selected` определяет исходный выбор, `details` объясняет назначение файлов. Удаление выполняется по одному файлу; папки удаляются только через `rmdir`, если пусты.

- `temp`: `%LOCALAPPDATA%\Temp`, `%SystemRoot%\Temp`, абсолютный путь `%TEMP%` и `%SystemRoot%\Prefetch\*.pf`. Одинаковые пути и пересекающиеся результаты не считаются дважды. Некорректная `%TEMP%`, корень диска, родительские каталоги профиля/AppData/Windows и системные ветки Windows вне Temp исключаются.
- Для Prefetch исходный выбор выключен. `Layout.ini`, базы и трассы не входят в правило `*.pf`. Возраст и исключения применяются как к остальным файлам. Prefetch помогает загрузке приложений; удаление может замедлить первые запуски до пересоздания кэша ([Microsoft, Windows internals](https://download.microsoft.com/documents/uk/technet/downloads/technetmagazine/24_32_inwinkernel_desfin.pdf)).
- `safety.py` исключает symlink, NTFS junctions, mount points и hard links. Перед удалением сверяются допустимый корень, тип, возраст, размер, идентификатор и время изменения. Свежие, изменённые и занятые файлы сохраняются.
- Кэши работающих приложений пропускаются по известным именам процессов. Ошибка получения списка процессов запрещает очистку таких кэшей. Проверка повторяется во время операции.
- Собственные данные SCleaner исключаются. Отказ доступа отражается в примечаниях/истории и не прерывает обработку доступных целей.

Проверка и удаление не являются атомарной операцией: изменение файла другим процессом между ними остаётся ограничением. Лимит сканирования — 250 000 файлов. Объём освобождения — логический размер удалённых файлов, а не замер свободного места.

## Реестр

`registry.py` проверяет Uninstall в HKCU/HKLM, представления 32/64 бит. Кандидату нужны название, отсутствующие каталог установки и исполняемый деинсталлятор на доступном локальном фиксированном диске. MSI, системные компоненты, записи Microsoft, дочерние обновления и записи с подразделами пропускаются.

`software_registry.py` анализирует ограниченные деревья HKLM\SOFTWARE без списка названий программ: пути в значениях, аргументы запуска, переменные окружения, REG_MULTI_SZ и вложенные ключи. Для обнаружения по путям нужны отсутствующая папка установки и связанный исполняемый файл; существующие и недоступные пути блокируют предложение. Проверяется установленное ПО обеих разрядностей в HKCU/HKLM, названия сравниваются по целым словам. Неполное чтение списка установленного ПО отключает этот поиск.

Системные ветки, драйверы, ссылки и недоступные деревья исключаются. Ограничения одной рассматриваемой ветки: 128 ключей, 8 уровней вложенности и 1 МиБ сериализованных значений. Родитель и дочерняя ветка одновременно не предлагаются; установленный соседний продукт блокирует удаление всей ветки издателя.

Пустые ключи и настройки без доказательств отсутствия программы попадают в ручную проверку. Они выбираются индивидуально, массовый выбор их не отмечает. Подтверждение удаления программы привязано к точным ID выбранных записей и не отменяет защиту установленных/системных компонентов.

Перед удалением создаются полные `.reg` (UTF-16) и JSON-копии с типами значений, структурой и разрядностью. Восстановление проверяет контрольную сумму и не перезаписывает отличающиеся существующие данные. Разрешения доступа не сохраняются. Очистка дерева не транзакционна: при частичном удалении полная копия остаётся доступной. Это не точка восстановления Windows.

## Данные и интерфейс

`%LOCALAPPDATA%\SCleaner` содержит `settings.json`, `history/*.json`, журнал каждого объекта `history/*.jsonl` и `backups/<операция>/*.{reg,json}`. Журнал должен быть доступен до первого удаления. После аварийного завершения JSONL может быть полнее сводки JSON. Логи содержат локальные пути.

Изменённые категории сразу влияют на следующее сканирование; кнопка сохранения настроек сохраняет их между запусками. Цвет сохраняется отдельно, с предпросмотром, отменой и сбросом. Длительные операции выполняются в фоне с отменой.

Снимок интерфейса без сканирования:

```powershell
.\.venv\Scripts\python.exe run.py --screenshot artifacts/overview.png --data-dir artifacts/preview-data
```

## Установщик и релиз

`build.ps1` запускает тесты, создаёт значок, собирает PyInstaller onedir, проверяет запуск `.exe` из другой папки, упаковывает ZIP и вызывает `build-installer.ps1`. Для сборки без установщика есть `-PortableOnly`. Фиксированные версии Python-зависимостей указаны в `requirements-build.txt`.

`installer/SCleaner.iss` использует Inno Setup 6.3+, русский и английский языки, установку для текущего пользователя без запроса администратора. Каталог по умолчанию — `%LOCALAPPDATA%\Programs\SCleaner`. Стабильный `AppId` позволяет обновлять существующую установку; не меняйте его при смене версии ([Inno Setup: AppId](https://jrsoftware.org/ishelp/topic_setup_appid.htm)). Перед заменой занятых файлов установщик использует Restart Manager; принудительное закрытие не включено.

Перед созданием рабочего окна и блокировкой данных `elevation.py` проверяет права и перезапускает приложение через `ShellExecuteExW` с `runas`. Это вызывает штатный запрос UAC ([Microsoft: ShellExecute](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew)). Работает для EXE, ярлыков и Python (`run.py`, `-m scleaner`, установленной команды `scleaner`). Путь данных передаётся абсолютным, чтобы сохранить прежние настройки. Отмена UAC завершает запуск; ошибка отображается отдельно. Внутренний флаг `--elevated` предотвращает повторный запрос, если Windows не предоставила права. Уже повышенный процесс продолжает работу без перезапуска.

Режим `--screenshot` только создаёт снимок и завершает работу, поэтому не требует UAC. Манифест EXE остаётся `asInvoker`; обычный запуск повышается в коде. Автоматические тесты проверяют маршрутизацию запуска, отмену и ошибки через имитацию Windows API; проверки сборки и установщика используют режим снимка.

Qt/Python остаются отдельными файлами. Деинсталляция удаляет установленные файлы и ярлыки, сохраняя пользовательские данные. Рекурсивных правил `[UninstallDelete]` нет. Сборка установщика автоматически ничего не устанавливает и не публикует.

Проверка готового установщика:

```powershell
.\.venv\Scripts\python.exe tools/verify_installer.py
```

Проверка устанавливает приложение в уникальную папку внутри `artifacts/installer-tests`, запускает его с тестовыми данными, повторно устанавливает ту же версию и удаляет её. Проверяются состав файлов, запись удаления, сохранение настроек/истории/копий и чужого файла в каталоге установки. Ярлыки при автоматической проверке отключены. Если SCleaner уже установлен, проверка отказывается изменять его запись; используйте чистую Windows VM. Журналы остаются в `artifacts/installer-tests`.

Перед публикацией также проверьте мастер установки и ярлыки на чистой Windows 10/11 x64. Цифровая подпись и загрузка файлов в GitHub Releases выполняются отдельно. Текст релиза находится в `RELEASE_NOTES_1.2.0.md`.
