# Free / Pro: тестовая реализация

Добавлены окно сравнения Free/Pro, импорт подписанного файла, активация ключом,
локальный сервер покупок и адаптер Stripe **только для test mode**. Новые платные
функции пока не реализованы: в интерфейсе они явно отмечены «В разработке».
Вся существующая очистка, история, исключения и восстановление реестра остаются Free.

## Быстрая проверка без платёжного аккаунта

Из корня проекта установите зависимости и создайте отдельное тестовое окружение:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m tools.license_sandbox --issue-for artifacts/pro-sandbox/app-data
```

Команда создаёт в `artifacts/pro-sandbox` открытые настройки `client-test.json`,
секретный **тестовый** ключ `issuer-private.pem` и файл `test-license.sclicense`.
Существующий ключ сохраняется при повторном запуске. Эти файлы игнорируются Git
и не входят в сборку приложения. Никогда не используйте этот ключ для продаж.

В первом терминале запустите локальный сервер:

```powershell
.\.venv\Scripts\python.exe -m scleaner_server.server --data-dir artifacts/pro-sandbox
```

Во втором терминале запустите приложение:

```powershell
.\.venv\Scripts\python.exe run.py --data-dir artifacts/pro-sandbox/app-data --license-test-config artifacts/pro-sandbox/client-test.json
```

При обычном интерактивном запуске приложение сохраняет штатный запрос UAC.
Тестовые настройки и путь данных передаются в повышенный процесс.

1. Откройте «Free · О версии Pro» в боковой панели или «Настройки → Free / Pro…».
2. Нажмите «Тестовая покупка». В браузере появится локальная форма без ввода карты.
3. Нажмите «Подтвердить тестовую покупку».
4. Вернитесь в приложение и нажмите «Проверить покупку» — появится «Pro · тест».
5. Закройте приложение, остановите сервер через Ctrl+C и снова запустите приложение
   той же командой. Подписанная лицензия продолжит работать офлайн.

Альтернативная проверка без сервера: в том же окне выберите «Импорт лицензии…»
и файл `artifacts/pro-sandbox/test-license.sclicense`. Он привязан к указанному
выше каталогу данных. Покупка по ключу и импорт используют один проверяющий модуль.

Лицензия действует 7 дней. При истечении срока вернётся Free. Повторная активация
ключом не продлевает срок. Для новой проверки можно создать новую тестовую покупку.
Отмена оплаты ничего не активирует. При повреждённом файле или недоступном сервере
текущие функции Free сохраняют работоспособность.

Снимки окна без сканирования или удаления:

```powershell
.\.venv\Scripts\python.exe -m tools.render_pro_preview
```

Результат: `artifacts/pro-preview/free-pro.png`, `pro-activated.png`, `overview.png`.

## Подключение Stripe в тестовом режиме

Stripe [поддерживает продавцов из Польши](https://stripe.com/global). Для следующей
проверки требуется собственный Stripe-аккаунт с test mode / sandbox. Реальный запрос
к Stripe в этой реализации пока не проверен: аккаунт и тестовые реквизиты не предоставлены.

1. В тестовом окружении Stripe создайте продукт SCleaner Pro с разовой ценой.
   Валюта и сумма задаются в Stripe; приложение не передаёт сумму для изменения цены.
2. Установите и авторизуйте официальный Stripe CLI. Запустите перенаправление событий:

   ```powershell
   stripe listen --forward-to http://127.0.0.1:8765/v1/stripe/webhook
   ```

3. В отдельном терминале задайте переменные **только для серверного процесса**:

   ```powershell
   $env:SCLEANER_STRIPE_SECRET_KEY = 'sk_test_REPLACE_LOCALLY'
   $env:SCLEANER_STRIPE_WEBHOOK_SECRET = 'whsec_REPLACE_FROM_STRIPE_LISTEN'
   $env:SCLEANER_STRIPE_PRICE_ID = 'price_REPLACE_WITH_TEST_PRICE'
   .\.venv\Scripts\python.exe -m scleaner_server.server --data-dir artifacts/pro-sandbox --provider stripe-test
   ```

   Подставляйте значения локально. Не отправляйте их в чат, не сохраняйте в репозиторий
   и не включайте в клиентскую конфигурацию. Ключи `sk_live_` сервер отклоняет.
   Локальный mock-сервер на том же порту предварительно остановите через Ctrl+C.

4. Запустите приложение с тем же `--license-test-config`, создайте **новую** покупку
   и завершите её на странице Stripe тестовыми реквизитами из
   [официальной документации](https://docs.stripe.com/testing).
5. После серверного подтверждения нажмите «Проверить покупку» в SCleaner.

Переход на страницу возврата из браузера сам по себе не выдаёт лицензию. Сервер
проверяет подпись webhook, допустимость его времени, test mode и соответствие
покупке. Затем запрашивает сессию у Stripe и выдаёт ключ только при `payment_status=paid`.
Повторные события и параллельные активации обрабатываются в транзакции SQLite.
Обрабатываются `checkout.session.completed` и `checkout.session.async_payment_succeeded`.

Документация: [Checkout fulfillment](https://docs.stripe.com/checkout/fulfillment),
[webhook signatures](https://docs.stripe.com/webhooks),
[создание Checkout Session](https://docs.stripe.com/api/checkout/sessions/create).

## Архитектура и границы этапа

- `scleaner/licensing.py`: Ed25519-проверка подписи и полей лицензии, сохранение,
  повторная проверка прав перед операцией через `LicenseManager.require(feature)`.
- `scleaner/pro_dialog.py`: окно Free/Pro, импорт и фоновые операции с сервером.
- `scleaner/activation.py`: запросы только по действиям пользователя, таймауты,
  ограничение размера ответа и запрет перенаправлений активации.
- `scleaner_server/`: отдельный локальный сервер, подпись лицензий и Stripe test adapter.
  Этот пакет не входит в установку Python-пакета SCleaner или исполняемый файл.
- `tools/license_sandbox.py`: создание локальных тестовых ключей и подписанных файлов.

В обычном запуске нет доверенных тестовых ключей и нет адреса сервера. Продажи и
импорт отключены. Тестовый режим включается только явным `--license-test-config`.
Данные тестовых лицензий находятся в `<data-dir>/licensing-test`, отдельно от обычных
`<data-dir>/licensing` и от `settings.json`. Изменение `is_pro` в настройках ничего не даёт.

Лицензия подписывает schema, key_id, product, edition, environment, license_id,
device_id, issued_at, expires_at, major_version и features. Текущая возможность
`pro_preview` предназначена для проверки доступа; она не означает наличие расписания
или профилей. При добавлении этих функций нужны собственные разрешения и проверки
в обработчиках операций, включая фоновые вызовы.

Код установки — случайный UUID, сохранённый локально. Аппаратные серийные номера,
результаты сканирования и пути к файлам серверу не передаются. Это привязка к
установке, а не строгая аппаратная защита: копирование всей папки данных клонирует
идентификатор. Удаление папки данных создаёт новую установку. Перенос лицензии,
восстановление по email и аккаунты в этом этапе не реализованы.

Сервер привязан только к `127.0.0.1`; он предназначен для разработки, а не для
публикации в интернете. Ключ покупки хранится в локальной тестовой базе и показывается
на странице заказа; письма не отправляются. Нет реальных списаний, production-конфигурации,
возвратов, отзыва лицензий, ограничения частоты запросов и управления устройствами.
Для публичного сервера нужны отдельная эксплуатационная конфигурация, HTTPS,
защищённое хранение ключей, восстановление покупок и правила возврата/переноса.
Длительная офлайн-лицензия не поддерживает мгновенный отзыв на отключённом ПК.

Проект распространяется по лицензии CC BY-NC-ND 4.0. Цифровая подпись защищает целостность
лицензии, но не предотвращает изменение открытого клиентского кода. Модель
распространения будущих платных компонентов требует отдельного решения.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Новые проверки покрывают подпись и подмену данных, истечение срока, другую установку
и версию, изоляцию test/production, ошибки сохранения, покупку/отмену, повторные
события, конкурентную активацию, перезапуск без сети и интерфейс Free/Pro.
Stripe HTTP API в тестах заменён имитацией; реальные Stripe-платежи не выполняются.
